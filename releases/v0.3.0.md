# Remote agents, and et for light/dark that follows you

Yoohoo can now show agents from an optional Agentd Hub and open them, and it
can reach remote ones over Eternal Terminal so remote apps follow your
desktop's light/dark mode.

- **Agentd Hub.** With `[agentd_hub]` enabled, agents that need you appear in
  the menu alongside native windows. Selecting one focuses its existing window
  when Yoohoo can find it, or opens Ghostty attached to its tmux pane.
- **Eternal Terminal.** New `[agentd_hub] transport = "auto" | "et" | "mosh" |
  "ssh" | "local"`. `auto` uses et when this machine has `et` and the host's
  etserver answers, then mosh, then ssh. Over et, apps in a remote tmux follow
  Ghostty's light/dark mode; mosh cannot relay it. mosh is unchanged and still
  preferred when et is not set up.
- **One connection check per host.** The first open on a host checks whether
  etserver answers and UDP reaches mosh's ports, and remembers it for a week in
  `~/.local/state/window-attention/transport-capabilities/`. Your config is
  never rewritten. A check that times out changes nothing: Yoohoo connects
  mosh-first as before.
- **ssh fallback in the window.** If et or mosh cannot start, the same window
  falls back to `ssh -tt`. A normal detach never reconnects. ssh launches now
  always request a PTY, so `tmux attach` works over plain ssh.
- **Bundled resolver 0.2.0** from
  https://github.com/clickety-clacks/agent-window-resolver, with its commit
  recorded in `payload/agent_window_resolver/VENDORED.json` and checked by the
  install test. It recognises et windows and reports its version in every
  response.

## Install or update

Download both assets into the same directory:

```bash
sha256sum -c SHA256SUMS
tar -xzf yoohoo-0.3.0.tar.gz
cd yoohoo-0.3.0
python install.py install
```

Existing personal settings are preserved; an existing `config.toml` keeps
working and means `transport = "auto"`. To use et, install Eternal Terminal on
both machines (Arch/AUR: `eternalterminal`, not `eternal-terminal`) and run
`etserver` on the remote host.

Compatibility remains Lua-based Omarchy, validated on Hyprland 0.56.2. The et
path was verified on a test machine with a stand-in terminal (see `docs/et-transport.md`);
a real Ghostty window over et has not been tested yet. Launchers outside Yoohoo
keep their own transport choice; this setting does not change them.
